## Legacy vocabulary stripped from documentation (6)

A C# developer maintaining this must never need to know what a PIC clause
is, so these comments were sanitised before emission. The useful half of
each sentence is kept. Listed because it signals the design prompt still
leaks storage detail into prose.

| Where | Original comment |
|---|---|
| `Account.Id` | PIC 9(11) — 11-digit numeric identifier |
| `CardCrossReference.CardNumber` | 16-character card number, PIC X(16) |
| `CardCrossReference.CustomerId` | PIC 9(09) — references a customer record (customer entity not in scope of this feature) |
| `CardCrossReference.AccountId` | Each card is issued against exactly one account; the cross-reference owns the FK. Proven from XREF-ACCT-ID -> ACCOUNT-RECORD.ACCT-ID. |
| `Transaction.Id` | PIC X(16) — generated by incrementing the last transaction ID |
| `Transaction.CardNumber` | Each transaction is posted against a specific card. The transaction owns the FK. Proven from TRAN-CARD-NUM -> CARD-XREF-RECORD.XREF-CARD-NUM. Account is reached via the multi-hop route through card_cross_references — no direct FK to accounts. |
